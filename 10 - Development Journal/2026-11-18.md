- MODO BASS: a generated Dalnok project with MODO BASS 2 (`au:aumu:MBS2:Ikmm`) renders headlessly in 3.2 s including AU instantiation, and opening the same project in the release app left the main thread idle. No multi-minute stall reproduced, so I am not calling it fixed. Reading the code, the reason it *can* happen is plain: `dalnok_project_apply` runs `Engine::instantiatePlugins()` on the caller's thread, and `EngineBridge.importForeign` applies on the main actor, so every plug-in initializes on the AppKit main thread. A plug-in that waits on main-queue work from inside its own init blocks there, and the CLI never hits it because it has no AppKit run loop. That is a design fix (background instantiation with a state the UI can show, or the separate host process), not a one-line move.
- Logic import gaps stay untouched on purpose. Tempo and meter changes, automation, routing, stacks and native processors each need Logic-saved bytes; guessing offsets from public notes would produce a plausible-looking but wrong tempo map, which changes every clip's time. The next useful artifact is a disposable Logic project saved from Logic with one tempo change, one meter change and one stack, kept in the scratchpad.
