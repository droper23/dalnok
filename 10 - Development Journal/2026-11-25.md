# 2026-11-25

## Parity worktree (`feat/parity-2`)
- **Sampler zones.** Dalnok Sampler now has 16 zones (it had one). Each zone holds a key range, a velocity range and a root, packed into one atomic so the audio thread reads a map without a lock. A zone with no map follows the Root Key parameter, so one-sample projects load and save exactly as before (no `zones` key in the state). An older state loaded onto a multi-sampled Sampler clears the zones it doesn't name.
- **Mapping by file name.** File names are mapped with C4 = 60, the convention the piano roll uses. Each zone reaches halfway to its neighbours. Files on one note split the velocities. If no file is named, the files go one per key from C4. If only some are named, the unnamed ones are skipped and listed.
- **Testing.** Engine tests are in `SamplerZones`. A mutation that ignores velocity fails the layer test. The self-test step is in `SelfTest+ClipEditor.swift`.
- **Matrix flake.** Four transport-timing checks failed in one 4-way matrix run (F.FWD, PAUSE, STOP) and passed on a 2-way rerun.
- **Guitar review.** Two reviewer agents went over the main tree's Guitar Tune and Guitar Studio work (a880a73, 72fec5f). The owner then asked for every finding to be fixed ("Guitar review fixes" below), and for both branches to be merged into main.


## Guitar Studio becomes a modular rig
The owner asked for Guitar Studio to replace separate chorus, flanger, reverb, compressor and similar plug-ins. It is now
eight slots of 20 original modules (ADR-0017 revised). Design choices:
- Modules live in ordinary parameters (module, switch, six knobs per slot), with titles, text, defaults and
  visibility following the module, so no C API or project-format change was needed.
- The first alias test failed at 48 kHz (−31 dB): the 39th-43rd harmonics of a near-square clip fold back even at 4x.
  First-order ADAA on every clipper fixed it; the filter itself measured as designed (−46.6 dB at 31.5 kHz).
- The gate's release now moves in decibels; a linear-gain release left noise only −53 dB down after 250 ms.
- Not done: a dedicated pedalboard view (the pedalboard look crowds the chain onto one pedal), undoable module edits,
  listening tests.

## Guitar review fixes
Two reviewer agents went over the guitar work. Their findings, and what was done:
- **Tune's hollow sound (confirmed).** After a correction, the two delay heads stayed straddled, which formed a comb filter. A new test measures the in-tune output against the input: without the fix it's off by 0.37 on a 0.3 signal; with it, under 1e-4. The span is now even, so the reported latency is exact at 44.1 kHz too.
- **High notes.** At a 12 kHz analysis rate they were 4-10 cents off. Moving the vertex onto the normalized function alone didn't fix it. The analysis rate went up to ~24 kHz (32 ms window), with the lags spread over samples; notes up to 1.3 kHz now land within 3 cents.
- **Old Studio states.** States from the fixed-chain version are translated to an equivalent rig, with a test.
- **Block-size dependence.** Knob smoothing depended on the host's block size. Mutation check: 5.6 dB apart between 8- and 64-frame blocks, now within 0.1 dB.
- **Audio-thread checks.** The blanket `-Wfunction-effects` exemptions are gone from guitar_modules/studio/tune. Libm calls pass the check anyway, and a malloc inserted for the test was caught.
- **Not changed.** Choosing a module still resets the slot's knobs. It's documented and the app relies on it. The Empty slot's Module parameter is now non-automatable. There is still no transport reset hook for tails (an engine-wide interface change).
- **UI.** The slot strip went into the header row on faceplates; its own row pushed the header out of the unit. On the pedal it gets a row of its own.
