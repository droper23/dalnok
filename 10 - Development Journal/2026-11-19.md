## A-08 deferred plug-in activation
- Plug-in creation can't move off the main thread (CLAP create/init and VST3 setup are main-thread calls; many AUs assume it), so ADR-0013 keeps it there and splits apply instead: the model goes live with every slot queued, then the app activates one per run-loop turn.
- Engine: `ApplyMode::{load, recover, defer}`, a FIFO of queued slot ids, `activateNextPlugin` (skips removed or already-loaded slots, times the init, commits), `cancelPendingPlugins`, `reloadPlugin`. UI-visible changes from loading bump the revision without marking the project edited. C API 32 adds `dalnok_project_apply_deferred`, `dalnok_plugins_pending/activate_next/cancel_pending`, `dalnok_plugin_reload` and `DalnokPluginSlotInfo.loading`.
- App: open and import use deferred apply; `Session.activatePendingPlugins` sleeps 1 ms between plug-ins so the window draws and Stop is handled. The status line shows "Loading plug-ins n of N…" with a Stop button; the track menu offers Load for unloaded slots (also useful after recovery). The device panel and mixer now rebuild when a slot's loaded state or message changes; before, a plug-in that loaded later would have kept its "not loaded" view.
- First test run found the fixture's in-memory media wasn't saved with the project (silence); switched to a WAV on disk. The first self-test run showed "Opening…" over the progress line; progress now replaces the transient message.
- `DeferredActivation` (3 tests) and the self-test's deferred-loading checks pass; Graphite self-test 533 checks.

## A-10 fuzzing and property tests
- Apple clang has no libFuzzer runtime; Homebrew `llvm@22` does. `scripts/ci/fuzz.sh` compiles the engine with `-fsanitize=fuzzer-no-link,address` into `.build/fuzz` (rebuilds everything when a header changes: a stale object after `zip.hpp` changed produced a bogus stack-buffer-overflow). Homebrew clang with the SDK needs `-include float.h` for the AppKit `.mm` files and pugixml only; forcing it everywhere breaks `<cmath>`.
- One target, first byte selects the format. Containers are wrapped so mutations reach the real parser: `.als` is gzipped, DAWproject gets a valid stored zip, Logic gets a package with the bytes as ProjectData; one variant feeds raw bytes to the zip reader. Projects apply in recovery mode, so fuzzed plug-in paths never load code. Seeds: the four generated projects, small hand-written documents per importer, and the generated Logic layout exported by `LogicImport/parsesFilesRegionsAndPlacements` (`DALNOK_FUZZ_SEED_DIR`).
- Finding 1 (seconds in): ZIP reader allocated the directory and entry sizes the archive claimed. Now every size and offset is checked against the file length, stored sizes must match, and deflate claims above ~1032:1 are rejected. `zipSizesAreCheckedAgainstTheFile` measured +4096 MB peak RSS on the old code.
- Finding 2 (after ~690k inputs): `%zz` in an FCPXML media URL threw `std::invalid_argument` from `std::stoi`; `adjust-volume` used unguarded `std::stof`. Malformed escapes now stay literal; volumes parse with `strtod`, finite and clamped. `importProject` and `dalnok_project_prepare` also catch at the C boundary. `fcpxmlMalformedEscapesAndVolumesImport` aborted on the old code.
- Exit-time LSan reports were threads still running (libFuzzer's RSS thread, the kept engine's stretch worker): the engine is destroyed at exit and the libFuzzer thread is suppressed.
- Final: 10-minute run, 834,391 inputs, clean; the four earlier findings replay clean (kept in `.build/fuzz/regressions`). Property test: seeded, 1,000 models with buses, sends, plug-ins and tempo/meter maps, pass (5 s). `scripts/check.sh` now always runs 33 parser/import tests under ASan (+13 s).

## A-01 stage 1: out-of-process plug-in hosting
- ADR-0014. `dalnok-plughost` (tools/dalnok-plughost, a C main calling `dalnok_plughost_main`) is built from the engine library, so the VST3/CLAP/AU hosts run unchanged inside it. One process per instance; built-in plug-ins stay in-process.
- Audio: one shared-memory block per instance (inputs, outputs, sidechain, notes, block-rate automation) with `request`/`done` counters, woken through `os_sync_wake_by_address_any`/`os_sync_wait_on_address(_with_timeout)` in shared mode (macOS 14.4+; older systems spin). The engine's audio thread waits at most 40 % of the block period (offline: 10 s), passes dry/silent when late, and never re-requests while the host is busy, so the host never reads a buffer being rewritten. The wake/wait is the declared `-Wfunction-effects` exception, like the plug-in call itself. The host's processing thread uses a time-constraint policy.
- Control: length-prefixed requests over a socket pair (5 s timeout), served on the host's main thread from a CFFileDescriptor run-loop source. The host `_exit`s when the socket closes.
- Failure: `poll()` (from `collectGarbage`) reaps a dead host or kills one that missed ~2 s of deadlines; the slot reports the reason (`loaded = false`, error with "Load restarts it"); offline renders skip failed instances, matching what is heard; `reloadPlugin` replaces a failed instance from saved state.
- Opt-in: `DALNOK_PLUGIN_HOST` (engine default, for tests/CLI) and Settings ▸ Plug-ins ▸ Safety in the app (`Engine.isolatePlugins`, host binary next to the app; `scripts/bundle.sh` copies it).
- Testing found two app-killing bugs before they shipped: writing to a crashed host's socket raised SIGPIPE in the engine process (now `SO_NOSIGPIPE`), and the crash path called `exitReason()` twice, so the second call (after reaping) recorded an empty failure that read as "loaded".
- Evidence: `scripts/ci/plugin-isolation.sh` — PluginHosting, DelayCompensation and ClapHosting all pass with every plug-in isolated (17 tests; two editor assertions now expect no editor when isolated), and PluginIsolation (bit-exact null against in-process; crash mid-session reported, project intact, reload restores processing; hang bounded per block and reported; crash/hang while loading fail only the load). Release overhead with the test gain VST3: in-process 1.2/2.2/4.2 µs p50, isolated 33.6/34.3/34.7 µs p50 (p99 ≈ 47 µs) at 64/128/256 frames. Self-test: Safety routes new plug-ins to the host and an Apple AUDelay loads isolated (Graphite 538).
- Not done: editors out of process, default-on after a pass over the owner's plug-in library, a per-callback deadline budget shared across isolated plug-ins, audio-workgroup membership for the host thread.
