## Tempo and meter maps (Phase 3 closed)
- Kept MIDI stored in frames and made every tempo edit a remap through beats (old map → new map) rather than migrating
  the model to beat-domain storage. This keeps every edit path, the C API and the UI unchanged, and handles the cases
  the earlier review flagged: notes crossing a change map each endpoint separately, and a note list shared by clips
  at different origins is split per origin while split pieces (same origin) keep sharing. Cost: up to one frame of
  rounding per tempo edit.
- Metronome clicks are scheduled from tempo and meter segments in the RenderState (no libm on the audio thread).
- The control bar edits the tempo/meter segment under the playhead; Transport menu adds and removes changes.
- Marquee clip selection finished and committed from the previous session's work in progress.

## Overhaul part 1
- Header scroll bug root cause: the header column and launcher had no `scrollWheel`, and header knobs consumed wheel events. Fixed with one shared viewport (`TrackScrollHost`).
- The engine had no plug-in bypass, so a pedal footswitch would have been a dead control. Added bypass end to end.
- Pedals are generated from a parameter set, seeded by the plug-in name (owner: no hand-designed pedals; any new plug-in gets one).
- Reels: previously 1.2 pt/s of tape. Now 43 pt/s (15 ips scaled) and Δθ = 2π·Δr/h.
- Real input (the owner asked for it this session): scroll over the headers, footswitch click, knob drag, ⌘S/⌘Z, ⌘K palette and Edit Controls popover dismissed by an outside click and by Escape. All behaved correctly. A first popover retest looked broken, but the outside click had landed on a lane and selected another track. Not a bug.

## Overhaul parts 2–3
- Built the shortcut registry around the menu (the menu already was the command system) instead of a parallel one.
- The self-test caught a real dispatch bug in an odd way: freeing K let AppKit match a plain K to Count-In (⇧K), and
  the count-in left on made later recording checks fail. Bisected with `DALNOK_SKIP_SHORTCUT_TEST`.

  window was key (`acceptsFirstMouse` is asked of the deepest view).

  Killing test instances left a session marker in the owner's Application Support, which made the next launch offer
  crash recovery. I removed it; runs now use `DALNOK_RECOVERY_DIR`. I restored the preferences the tests changed.
  One ⌥⌘K check was sent while Dalnok wasn't frontmost, so it went to whichever app was in front.
