## Late night: clip editor, quantize (MIDI and audio), editing fixes

The owner listed what a session in Dalnok was missing. Done, branch `feat/clip-editor-quantize`:
- **Docked clip editor** (`ClipEditorPanel.swift`): double-click opens a clip in the bottom area (piano roll, or a sample
  view for audio); a Clip / Devices switch shares the space with the device chain (`MainWindowController.bottomMode`).
  The floating piano roll window (Clip ▸ Piano Roll, P) stays. `pianoRollIsKey`/`activeRoll` route keys and Edit
  commands to whichever roll was clicked last.
- **Quantize like Logic:** `QuantizeSetting` (value incl. triplets, strength), Q in the arrangement (`midi.quantize_selection`).
- **Audio quantize** (`engine/src/audio_quantize.cpp`, API 47 `dalnok_audio_transients` / `dalnok_audio_quantize`,
  command `audio.quantize`): SuperFlux-style onset detection refined to the attack start; slices cut 6 ms before each
  attack, moved to the grid; each slice's first 50 ms played as is and only its tail stretched (Signalsmith). A first try
  fed the stretcher the real audio after each region instead of silence: that leaked the next hit backwards into the
  slice before it (pre-echo, heard as doubled hits in the test), so it was reverted and attacks were kept out of the
  stretcher altogether. Measured: hits land within 0.5 ms, correlation > 0.9 with the original hit, no clicks.
- Engine: an empty audio track becomes an instrument track when it gets an instrument plug-in or a MIDI clip;
  `dalnok_plugins_copy` (plug-in copy/paste with state).
- Fixes: MIDI clip right-edge resize collapsed the clip (clamped to audio media length, 0 for MIDI); ⌘C/⌘X/⌘V/⌘D were
  registered for the arrangement only and never reached the piano roll.
- Hover playhead line; Play from a selection (notes, clips, or a marquee section) made since the playhead was placed.
- Verified: `swift test` 297/297 (before the last test additions), AudioQuantizeTests, self-test matrix 12/12 PASS with
  the new `clipEditorSteps` (SelfTest+ClipEditor.swift).
- Open: audio quantize on real recorded drums is unheard by the owner; the sample view has no zoom-to-region button;
  the docked roll is short at the default height (drag its top edge).

Later: the owner wanted quantize to keep the clip whole. Audio quantize now writes a warp map on the clip
(`warp.hpp`, format 15) rendered by the stretch cache; trims and splits crop the map, saving keeps it. The render
compiler's change detector (ClipKey) didn't include the warp at first, so a quantized clip stayed silent until that
was added. Also fixed from the owner's notes: editor playheads; themed tabs/button; Graphite knobs drawn as Atelier
dials (a `case .knob, .selector where` guarded only `.selector`, present since the Prism/Atelier commit, visible once
Graphite returned to these knobs); Atelier dial light bars under the skirt (now a paper band and the bars above it);
the drag bubble's stale fonts after a theme switch; Input Monitoring chose the built-in mic (macOS default input) when
the Scarlett was connected, and the Inspector's Monitor menu skipped choosing the device. Verified: 297 engine tests,
AudioQuantizeTests (in place, split, reopen), fuzz 60 s clean, self-test matrix 12/12, real-input self-test on the
Scarlett (both looks run).
