## Research
Steinberg relicensed the VST3 SDK to MIT in Oct 2025, which makes a permissive, independent engine
practical. JUCE is AGPLv3 or commercial. Tracktion Engine is GPLv3 or commercial and needs a JUCE
license too. Audacity 4.0 (Sep 2026) is a Qt6 rewrite without MIDI or a mixer. See [[Foundation Evaluation]].

## Built
Engine (C API, Core Audio, snapshots, transport, gain/pan/mute, media, peaks, offline render, WAV
export), macOS app, CLI, tests, and CI.

## Problems hit
- The macOS SDK declares `AURenderCallback` with the real-time effect, so our callback chain had to be
  `nonblocking` end to end. Kept, since it's a free safety net. A negative test proves violations fail the build.
- Apple clang 21 has no `-fsanitize=realtime`. RealtimeSanitizer is planned via Homebrew LLVM.
- One round-trip test failure was a test bug: the signal reached −1.006 full scale, which integer formats correctly clip.

## Tests
`swift test`: 10/10 (21 cases). Live CLI smoke tests: PASS. UI snapshot reviewed.

### CI crash after M4 (fixed)
CI segfaulted (signal 11) in the test run. Locally everything passed. AddressSanitizer pinpointed a
**test-only** use-after-free: the relink test released a media handle and then passed it to the API
again. Fixed, and a `sanitizers` CI job (ASan + TSan) now runs on every push, so this class of bug
fails deterministically. The engine itself was clean under both sanitizers, and so was the app self-test under ASan.

## Unified Open and Scarlett check
Open accepts native and foreign projects and stem folders; foreign selection asks Import or Cancel, and the separate import menu is removed. The picker filters by extension rather than depending on Logic UTI registration. Self-test covers Logic package eligibility and cancel/confirm import. ## Capture buffer and Scarlett channels
Added a preallocated SPSC interleaved capture buffer with all-or-nothing blocks and dropped-frame accounting. Native tests cover empty/full, oversize, wraparound, and 200,000 ordered stereo frames across two threads; normal and ThreadSanitizer runs pass. The buffer is not yet connected to hardware or a writer. A separate short AVFoundation capture reported identical very low peaks (-63 dBFS) on channels 1 and 2 and silence on 3 and 4; it does not prove an active microphone signal.

A later short Scarlett capture peaked at -29.2 dBFS on channels 1 and 2. Subtracting those channels gave digital silence: the capture path may duplicate one input, so this is not proof that the hardware inputs are independently working. Channels 3 and 4 were silent. Temporary audio was deleted.

## Capture writer foundation
Added an off-thread drain with independent overflow, write, and finalization error flags and frame counters. A temporary PCM spool creates files exclusively, flushes its header and final data, and permits read-only inspection of complete and partial frames. Native tests cover normal drain, overflow, injected write/finalize errors (including combined errors), file contents, no-overwrite, malformed headers, partial tails, and a write failure. Normal and ThreadSanitizer runs pass. These pieces are not connected to a device, model, UI, final audio file, or crash recovery; Phase 2 remains incomplete.

A separate process-kill test confirms the spool header and complete frames can be inspected after a writer process is killed before finalization; it does not simulate power loss or recover an actual project. A deterministic synthetic ten-second stereo capture preserved its frame count and checked sample values. Native normal, AddressSanitizer, and ThreadSanitizer runs pass.

A C API v5 snapshot operation writes a project copy without marking it saved or changing its revision. The persistence test verifies exact offline-render output after reload and preserves dirty state on success and I/O failure. All 66 engine tests pass. Automatic scheduling, recovery selection, and full Phase 2 remain unimplemented.

## Recovery snapshots
Added periodic snapshots of dirty model revisions into uniquely named files under Application Support/Dalnok/Recovery, retaining previous copies. File ▸ Recover Snapshot opens a copy as a new unsaved project; C API v6 provides the recovered apply operation. The self-test covers writing and restoring a copy, dirty state, and retaining the original. Engine tests verify exact audio and safe temporary files, including a symlink collision. All 67 engine tests pass. Timer scheduling and actual app-crash recovery remain unverified; no retention controls or automatic recovery prompt yet.

Follow-up: unique temporary project files now preserve an existing project file’s permissions when replacing it. The targeted persistence suite, including a mode-preservation test, passes.

The recovery smoke test now starts an isolated app with a system sample, waits for the periodic snapshot, kills that process, and successfully renders 71,638 frames from the snapshot. The script is repeatable with a GUI and output device. This does not test power loss or provide automatic recovery prompting.

## Capture spool recovery
Added a C API and CLI conversion from a stopped mono/stereo spool to a new float WAV. The source is never modified, an existing destination is not replaced, and partial trailing frame bytes are reported and omitted. Tests verify numerical samples, invalid input, unsupported channel counts, and no-overwrite. All 70 engine tests and native capture tests pass. ## Duplex capture, MIDI discovery, and UI audit
Added explicit audio-input discovery, experimental same-device AUHAL mono capture through the engine/CLI, timestamp discontinuity detection, and recovery to WAV. Scarlett Solo 4th Gen at 44.1 kHz: both input channels produced independent signals; 30 seconds captured and recovered with 1,323,520 frames and zero reported drops. Opt-in hardware tests cover the capture lifecycle and prevent output changes during a take. A writer stop race discovered under ThreadSanitizer was fixed and stress-tested. Track arm, monitoring, model placement, durable journal, latency calibration, and power-loss tests remain.
Core MIDI source discovery finds the MiniLab; a separate 15-second probe counted 9 note-on and 8 note-off events and saved no performance. A standalone MIDI 1 parser is tested, including running status, SysEx, overflow, and concurrency; it is not connected to live ports or a MIDI model.
A multi-perspective UI review is in [[UI Audit 2026-11-16 follow-up]]. Added Settings and Warm Analog; appearance takes effect on reopening. Improved faint text contrast and gain/pan labels. Both themes passed app self-tests and synthetic snapshot review. VoiceOver and broader usability testing remain.
